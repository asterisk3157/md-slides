# Markdown 仕様 (確定版)

pptx_auto における **入力 Markdown** の仕様。`docs/future_md_pipeline.md` で示された
パイプラインの入力フォーマットを、本ツールの実装制約（5ブロックレイアウト、
`handwriting_pptx/formula.py` の数式エンジン、辞書ベース手書き再現）に揃えて確定する。

対象バージョン: **MVP (Phase 4)** — `audit` / `generate` CLI の入力フォーマット。
互換性: 本仕様は **CommonMark の部分集合** を採用する。数式は **LaTeX 互換**
(Pandoc/MathJax 慣習に準拠)。

---

## 1. ファイル全体構造

### 1.1 ファイル形式

- 拡張子: `.md`
- エンコーディング: **UTF-8 (BOMなし)**
- 改行: LF / CRLF いずれも受理（内部で LF 正規化）

### 1.2 トップレベル構造

```
[フロントマター YAML]   ← 任意
[スライド1]
---
[スライド2]
---
...
```

- **フロントマター YAML** はファイル先頭の `---` で挟まれたブロック（任意）
- **スライド区切り** は **行頭の `---`** （3 文字以上のハイフン、前後空行推奨）
- スライドが 1 枚のみの場合、区切りは不要

### 1.3 フロントマターとスライド区切りの曖昧性の解消

ファイル先頭の `---` で始まるブロックは、**直後に YAML キーが続けば** フロントマター、
そうでなければ通常のスライド区切りとして扱う。

```markdown
---
color: "#004F8B"      ← YAMLキーがあるのでフロントマター
brush_width_cm: 0.086
---

# 1枚目
```

```markdown
# 1枚目

---                    ← 単なる区切り

# 2枚目
```

## 2. スライド構造

### 2.1 1 スライアド = 見出し 1 + 箇条書き ≤4 (= 5 ブロック)

`handwriting_pptx/layout.py` の 5 ブロックレイアウトに直接マップする。

```markdown
# 見出し                ← ブロック1 (h=1.8cm)

- 箇条1                 ← ブロック2 (h=1.0cm)
- 箇条2                 ← ブロック3
- 箇条3                 ← ブロック4
- 箇条4                 ← ブロック5
```

| Markdown 要素 | スライド要素 | 制約 |
|---|---|---|
| `# テキスト` | 見出し (1 行目) | スライドにつき **必ず 1 個** |
| `- テキスト` | 箇条書き行 | スライドにつき **0〜4 個** |
| `---` | スライド区切り | 行頭、前後空行推奨 |
| それ以外 | **MVP では無視 + 警告** | 段落、画像、コードブロック等 |

### 2.2 制約違反時の挙動

| 状況 | 挙動 |
|---|---|
| 見出し `#` がない | エラー: `slide N: heading required` |
| 見出しが 2 個以上 | エラー: `slide N: multiple headings` |
| 箇条書きが 5 個以上 | エラー: `slide N: max 4 bullets (got 5)` |
| 段落・画像など未対応要素 | 警告 + 該当行をスキップ |

### 2.3 見出し記法

- `# ` （`#` + 半角スペース + テキスト）のみ受理
- `## ` 以下のレベルは MVP では **エラー**（拡張余地として残す）

### 2.4 箇条書き記法

- `- ` （ハイフン + 半角スペース + テキスト）のみ受理
- `* ` や `+ ` は **エラー**（CommonMark 全部受けると曖昧性が増えるため絞る）
- 入れ子（インデント箇条書き）は **MVP では非対応**

### 2.5 メモ記法（note）

- `> テキスト` （引用記法）で **メモ** を表す
- 本文と同じ縦フローに **小さめ＋グレー** で配置（サイズは `note_pt`）
- 文中の `<span class>` 色指定は尊重し、無色部分のみグレー化

## 3. 数式記法

### 3.1 区切り記号

CommonMark/Pandoc/MathJax の慣習に従う。

| 種類 | 区切り | 用途 |
|---|---|---|
| **インライン数式** | `$...$` | 箇条書き行内・見出し内に混ぜる |
| **ブロック数式** | `$$...$$` | （**MVP では不採用 / 将来予約**） |

MVP では **インライン `$...$` のみ** をサポート。箇条書き 1 行が「テキスト + 数式 + テキスト」
の混合になっても良い（例: `- 公式: $x^2 + y^2 = r^2$ を覚える`）。

ブロック数式 `$$...$$` は **5 ブロック制約と合わない**（センタリングや大きさのデフォルトが
別になる）ため、Phase 5 以降で「数式のみスライド」レイアウト導入時に解禁する。

### 3.2 エスケープ

- 文中に `$` を文字として書きたい場合は `\$`
- バックスラッシュ自体は `\\`
- 数式内では LaTeX 通常通り `\\` で改行（**MVP では未サポート → 警告**）

### 3.3 数式構文 (formula.py 実装ベース)

`handwriting_pptx/formula.py` の `parse_formula()` がそのままパーサ。
本仕様で **対応を保証する記法** を以下に列挙する。

#### 3.3.1 基本

| 記法 | 意味 | 例 |
|---|---|---|
| `x` | 1 文字 atom | `x` |
| `{...}` | グループ | `{x+1}^2` |
| `x^2` | 上付き | `x^2`, `e^x` |
| `a_n` | 下付き | `a_n`, `x_1` |
| `x^2_n` | 上下同時 | `x^2_n` |
| `^{...}` `_{...}` | 複数文字の上下付き | `x^{n+1}`, `a_{ij}` |

#### 3.3.2 分数・ルート

| 記法 | 意味 |
|---|---|
| `\frac{a}{b}` | 分数 |
| `\sqrt{x}` | 平方根 |
| `\sqrt[3]{x}` | n 乗根（n が上付き指数） |

#### 3.3.3 大型演算子

| 記法 | 表示 |
|---|---|
| `\int_a^b f(x) dx` | 積分（下限・上限・被積分関数・微分 `dx` 自動縮小） |
| `\sum_{n=1}^\infty a_n` | 総和 |
| `\prod_{i=1}^n` | 総乗（要辞書: `∏`） |

#### 3.3.4 関数 (future_functions.md 準拠 / Phase 5)

| 記法 | 表示 | 必要辞書 |
|---|---|---|
| `\sin x` `\cos x` `\tan x` | sin x / cos x / tan x | `s i n c o t a` |
| `\log x` `\log_{10} x` | log x / log₁₀ x | `l o g 1 0` |
| `\ln x` | ln x | `l n` |
| `\exp x` | exp x | `e x p` |
| `\lim_{x \to 0} f(x)` | lim (下に x→0) f(x) | `l i m → x 0` |
| `\arcsin x` `\arccos x` `\arctan x` | arcsin x 等 | `a r c …` |

**自動縮小ルール（formula.py 実装済み）**:
- `f(x)` のような **関数呼び出しの引数** `(x)` は自動的に 0.55x で縮小
- `dx` `dt` などの **微分記号** は自動的に 0.55x で縮小

#### 3.3.5 ベクトル (future_vectors.md 準拠 / Phase 5)

| 記法 | 表示 |
|---|---|
| `\vec{v}` | v の上に小さな → |
| `\vec{AB}` | AB の上に → |
| `\vec{a+b}` | a+b の上に → |

#### 3.3.6 ギリシャ文字 (LATEX_MAP 既存対応)

`\pi` `\theta` `\alpha` `\beta` `\gamma` `\lambda` `\mu` `\sigma` `\phi` `\omega`

大文字 `\Pi` `\Sigma` `\Omega` `\Delta` などは Phase 5 で追加予定。
**MVP では大文字ギリシャは未対応 → エラー**。

#### 3.3.7 記号

| 記法 | 表示 | 備考 |
|---|---|---|
| `\leq` | ≦ | LATEX_MAP 登録済 |
| `\geq` | ≧ | |
| `\neq` | ≠ | |
| `\approx` | ≈ | |
| `\pm` | ± | |
| `\times` | × | |
| `\div` | ÷ | |
| `\infty` | ∞ | |
| `\to` `\rightarrow` | → | Phase 5 (要辞書登録) |
| `\cdot` | ・ (中点) | Phase 5 |

### 3.4 数式構文エラー時の挙動

- 未知の `\name`: **警告** + 該当 atom スキップ（formula.py 既存挙動）
- 閉じていない `{` `(` `$`: **エラー** + 行番号表示
- ネスト深さ 8 超: **警告**（実用では不要だが暴走防止）

## 4. メタデータ（フロントマター YAML）

### 4.1 ファイル全体に適用するキー

```yaml
---
color: "#004F8B"            # 全スライドのインク色 (デフォルト: "#000000")
brush_width_cm: 0.086       # ブラシ太さ cm (デフォルト: 0.086)
heading_pt: 50              # 見出しサイズ pt (役割別プリセット・推奨)
subheading_pt: 32          # 小見出しサイズ pt
body_pt: 28                # 本文(箇条書き/段落/数式/表)サイズ pt
note_pt: 18                # メモ(> ...)サイズ pt
slide_width_cm: 33.867      # スライド幅 (デフォルト: 33.867 = 16:9)
slide_height_cm: 19.05      # スライド高 (デフォルト: 19.05)
author: "user_name"         # 任意メタ情報
---
```

- **フォントサイズは pt の役割別プリセット**（`heading_pt`/`subheading_pt`/`body_pt`/`note_pt`）。
  指定したサイズは **行数に依らず固定**（自動縮小しない）。入り切らない場合はプレビューで赤く「はみ出し」警告。
- 旧キー `heading_size_cm`/`bullet_size_cm`(cm) も後方互換で有効。pt 未指定時は従来既定（見出し1.8cm・本文1.0cm・小見出し=本文×1.12・メモ=本文×0.62）。
- 未知のキーは **警告** + 無視
- 型が違う場合（例: `brush_width_cm: "thick"`）は **エラー**

### 4.2 スライドごとに上書きしたい場合（議論余地あり → §6 で 3 案）

MVP では「スライドごと上書きは非サポート」。全スライドで色・太さが一律。

### 4.3 `type` と `styles`（装飾レイヤー: 設計確定・実装進行中）

> 設計根拠は [design_decisions.md](design_decisions.md) §4–5。

```yaml
---
type: handwriting-slides    # このMDが手書きスライド用であるシグナル（任意）
styles:                     # 装飾クラスの定義（意味ロール）
  key:  { color: red,  bold: true }   # 重要・キーワード
  note: { color: blue }               # 補足・注釈
  weak: { color: gray }               # 控えめ
  teigi: { color: "#0a7", bold: true } # カスタムも自由
---
```

- `styles` は **3層マージ**: 組込みデフォルト(`key`/`note`/`weak`) → グローバルテーマ(D1) → 文書frontmatter。
- プロパティは v1 で **`color`・`bold`** のみ（将来 `size`）。任意CSSは不可。
- マージ結果が「使えるクラス一覧」の契約書。**未定義クラス参照はエラー**。

## 4'. 装飾（太字・色・役割）

### 4'.1 太字 / 斜体（標準MD・実装済み）

- `**太字**` → 手書きの太字（太いブラシ）。**実装済み**。
- `*斜体*` → 手書きでは斜体表現しないため **マーカーを剥がして中身だけ残す**。

### 4'.2 色・役割（インラインHTMLスパン: 設計確定・実装進行中）

body の装飾は **インライン HTML スパン**で書く（`<>` は数式と衝突しないため安全）:

```markdown
次の <span class="key">重要</span>な点、<span class="note">補足</span>です。
数式も色付け可: <span class="key">$x^2 + y^2 = r^2$</span>
```

- `class` は §4.3 の `styles` で定義した **意味ロール名**（生の色名ではない）。
- `<span style="...">` のインラインスタイル直書きは **非推奨**（冗長＋内容と見た目の癒着）。
- 太字とネスト可: `<span class="key">**重要**</span>`。
- デフォルト出力色は **黒**。色は明示した部分だけ付く。

## 5. サンプル (確定版)

### 5.1 最小例（フロントマター無し、1 スライド）

```markdown
# はじめての数式

- $x^2 + y^2 = r^2$
- $\sin^2 \theta + \cos^2 \theta = 1$
- $\int_0^1 x dx = \frac{1}{2}$
- $\vec{a} \cdot \vec{b} = 0$
```

### 5.2 フロントマター + 複数スライド

```markdown
---
color: "#004F8B"
brush_width_cm: 0.086
heading_size_cm: 1.6
bullet_size_cm: 0.9
---

# バーゼル問題

- $\sum_{n=1}^\infty \frac{1}{n^2} = \frac{\pi^2}{6}$
- $\int_0^1 f(x) dx$
- $\sqrt[3]{x+1} = y^2$
- $a \geq b, c \neq 0, p \leq q!$

---

# つぎのスライド

- ふつうのテキスト
- $x^2 + y^2 = r^2$
- $\sin \theta + \cos \theta$
- $\vec{v} \cdot \vec{w} = 0$
```

### 5.3 テキスト+数式 混合

```markdown
# 接線の本数

- 定義: 直線が曲線に接する
- 条件1: $f'(a)$ が傾き
- 条件2: $y = f(a)$ を通る
- 例: $f(x) = x^3 - 3x$ で 3 本
```

## 6. 議論余地ありの項目 (Claude メイン用、各 3 案提示)

確定版仕様としては **A 案を採用** しているが、後で変更したい場合の選択肢を残す。

### 6.1 数式区切り記号

| 案 | 記法 | メリット | デメリット |
|---|---|---|---|
| **A (採用)** | `$...$` のみ | MathJax/Pandoc/Obsidian 互換、エディタの拡張も豊富 | `$` をテキストで使うときエスケープ必要 |
| B | `` `$...$` `` (バッククォート併用) | エスケープ不要、CommonMark コード扱いと混ざらない | 非標準で他ツールと非互換 |
| C | `\(...\)` (LaTeX 純正) | LaTeX 経験者に自然 | Markdown では非主流、目視で気付きにくい |

→ A 採用。**理由**: Pandoc/Obsidian/Quarto 等のエコシステムに合わせるのが最も摩擦が少ない。

### 6.2 スライドごとの色・サイズ上書き

| 案 | 記法例 | メリット | デメリット |
|---|---|---|---|
| **A (採用 / MVP)** | 上書き非対応（フロントマターのみ） | 実装最小、仕様シンプル | スライドごとに色を変えたいとき不可 |
| B | スライド先頭に HTML コメント `<!-- color: "#FF0066" -->` | Markdown を壊さない、git diff に優しい | パース実装やや手間、可読性中 |
| C | スライド先頭の YAML フェンス（`---` の直後にもう一回 `---` ブロック） | フロントマターと記法統一 | 区切り `---` と紛らわしい |

→ A 採用。Phase 4.1 で需要があれば B に拡張。

### 6.3 レイアウト切替（5 ブロック以外） — ✅ フローレイアウト実装済み

MVP の固定 5 ブロックから **縦フローレイアウト** (`layout.py:layout_flow`) に拡張済み。
見出し + 可変個のコンテンツアイテムを縦に積み、入りきらなければ自動縮小する。
コンテンツアイテム: **箇条書き / 段落 / 小見出し(##,###) / ブロック数式 / 表**。
（タイトル専用・2カラム等の特殊レイアウトは引き続き将来課題。）

### 6.4 ブロック数式 `$$...$$` — ✅ 実装済み (案B採用)

`$$ ... $$`（1行・複数行どちらも可）を **中央寄せのブロック数式**として配置。
```markdown
$$
y = (3t^2 - 18t + 15)x - 2t^3 + 9t^2 - 7
$$
```

### 6.6 表（増減表など） — ✅ 実装済み

GitHub 記法の表をグリッド（罫線）＋セル内容で手書き描画する。
```markdown
| $x$ | $\cdots$ | $1$ | $\cdots$ |
|---|---|---|---|
| $f'(x)$ | $+$ | $0$ | $-$ |
| $f(x)$ | $\nearrow$ | きょくだい | $\searrow$ |
```
セル内は通常のインライン記法（数式・装飾）が使える。

### 6.7 段落・小見出し・コメント — ✅ 実装済み

- **段落**: 箇条書きマーカーの無い地の文を 1 行として配置（`・` なし）。
- **小見出し**: `## ` / `### ` を本文より少し大きい行として配置。
- **コメント**: 行全体が `<!-- ... -->` または `(* ... *)` の行は無視。

### 6.5 未登録文字の扱い (audit/generate 連携)

| 案 | 挙動 | メリット | デメリット |
|---|---|---|---|
| **A (採用)** | `audit` で列挙 + 登録 URL を提示。`generate` 実行時に未登録ありなら警告 + プレースホルダで生成 | パイプライン的に自然、生成は止まらない | 完成度の低い pptx が出る |
| B | `generate` 時に未登録ありで **エラー停止**（強制 audit 経由） | 完成度保証 | 試行錯誤がしづらい |
| C | `generate` 時に未登録文字を **自動で TTF フォールバック** で描画 | 中断なし、見た目も最低限保たれる | 手書き感が損なわれる、TTF 実装コスト |

→ A 採用。`--strict` フラグで B 相当の挙動に切替可能とする（CLI 仕様で吸収）。

## 7. 実装上の注意点 (パーサ実装者向け)

### 7.1 パイプライン

```
md text
  ↓ (1) フロントマター抽出 (PyYAML)
  ↓ (2) スライド分割 (`^---$` 正規表現)
  ↓ (3) スライドごとに見出し/箇条書き抽出
  ↓ (4) 各行内の $...$ を formula.parse_formula() に渡す
  ↓ (5) 残りはテキスト atom として concat
  ↓ (6) handwriting_pptx.Presentation.add_slide_5block() に投入
```

### 7.2 数式とテキストの混在表現

箇条書き 1 行 `- 公式: $x^2 + 1$ を覚える` は、`Math` と `Text` を交互に並べた
**ミックスブロック** として表現する。MVP では `Math` 専用 API しかないため、
`handwriting_pptx.api` に `MixedLine([Text("公式: "), Math("x^2+1"), Text(" を覚える")])`
を追加する必要がある（**md_spec.md の範疇外、別途実装計画で扱う**）。

### 7.3 audit 対象文字の抽出

- テキストはそのまま 1 文字ずつ
- 数式は `parse_formula()` 後の atom 列から `base` を再帰収集
  - `\frac{a}{b}` → `a`, `b`
  - `\sin` → `s`, `i`, `n` （関数名展開）
  - `\vec{AB}` → `A`, `B` （矢印自体はストローク合成なので辞書不要）
- ASCII 英数・基本記号は **辞書必須** から除外する案もあるが、本ツールは
  「全文字を手書きで」が前提なので **全部辞書必須**

### 7.4 行番号トラッキング

エラー・警告メッセージは `slide N, line M:` 形式で出すこと。
`---` を跨いだあとも元ファイルの行番号で。

## 8. 確定事項サマリ

| 項目 | 確定値 |
|---|---|
| エンコーディング | UTF-8 (BOMなし) |
| 改行 | LF/CRLF 受理、内部 LF 正規化 |
| フロントマター | YAML、ファイル先頭 `---` で挟む |
| スライド区切り | 行頭 `---` |
| 見出し | `# ` のみ、1 スライドに必ず 1 個 |

| インライン数式 | `$...$` |
| ブロック数式 | **未サポート (将来予約)** |

| レイアウト | 5 ブロックのみ (default) |

以上を **MVP の確定仕様** とする。
変更が必要になった場合は §6 の B/C 案を参照して拡張する。
