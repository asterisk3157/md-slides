# 設計決定記録 (Design Decisions)

pptx_auto の方針議論で確定した設計判断をまとめる。実装はこの方針に従う。
個別フォーマット仕様は [md_spec.md](md_spec.md)、ロードマップは [CLAUDE.md](../CLAUDE.md) を参照。

最終更新: 2026-05-19

---

## 1. プロダクトの核と境界

- **核 (moat)**: 入力記法ではなく **手書き筆跡の再現品質**（配置・書き順アニメ・辞書）。
  記法は後でいくらでも変えられるが、レンダリング品質は一朝一夕では出ない。
  → **記法の作り込みより、プレビュー/UI/辞書の充実に投資する。**
- **スコープ外**: 図・ダイアグラム。これらは PowerPoint で人間が手動追加する。
  ツールは **手書きテキスト＋数式** に集中する（当初構想どおり）。
- **入力記法と手書き辞書は疎結合**。未登録文字はフォールバック＋QR で登録誘導。

## 2. 入力ファイル形式

- **`.md`（Markdown スーパーセット）で行く。** 独自拡張子(.autopptx)は作らない。
  - 理由: LLM/人間の MD 習熟という最大の武器を捨てない。出力が手書きストロークなので
    HTML 化しても「ブラウザがタダで描画」の利点は効かない（活字とは別物）。
  - 判断基準: **標準 MD トークン (`**` `#` `-` `$…$`) を再定義しない限り `.md`。**
    再定義が必要になった瞬間が独自拡張子へ切り替えるシグナル（今は不要）。
- **graceful degradation を保つ**: 普通の MD ビューアで開いても意味が壊れないこと。
- **ツールは拡張子非依存**（中身で判定）。「特別さ」は frontmatter `type:` で表現する。

```yaml
---
type: handwriting-slides
---
```

## 3. 2層の記法と「意味/空間」の線引き

記法は2層構造にする:

- **tier 1（人間/LLM が素朴に書く）**: 標準 MD ＋ LaTeX サブセット数式（`$…$`）。
- **tier 2（詳細制御、AI に書かせる）**: 装飾（色・役割）など。

そして詳細制御の属性を性質で分ける（重要原則）:

| 属性の性質 | 例 | 制御方法 |
|------------|----|----------|
| **意味的・離散的** | 色・太字・役割(重要/補足) | **記法**（`.md` に書ける、AIが書く） |
| **空間的・連続的** | x/y 座標・サイズ・字間 | **プレビュー上のマウス操作 UI**（記法には書かない） |

> 「色は赤」とは言えるが「x=4.2cm」とは記法で言えない。この線引きを守る。

数式は **LaTeX サブセット**に寄せる（Word 線形式より LLM が圧倒的に得意）。

## 4. 装飾レイヤー（色・役割）

- **body の装飾はインライン HTML スパン** `<span class="key">…</span>` を使う。
  - 理由: `<>` は LaTeX 数式に絶対出てこない（`{}` や `<`/`>` の衝突を回避）。
    閉じタグ込みで LLM が事故りにくい。MD は元々インライン HTML を通す（正攻法）。
- **クラスは「意味ロール」**（案B確定）。生の色名ではなく役割名。
  - 理由: 「全部黒→部分色」がテーマ切替一発で実現。AI は「重要か?」を「赤か青か?」より安定して判断できる。
- **見た目は frontmatter / テーマの `styles:` に集約**（CSS の content/presentation 分離）。

```yaml
---
type: handwriting-slides
styles:
  key:  { color: red,  bold: true }   # 重要・キーワード
  note: { color: blue }               # 補足・注釈
  weak: { color: gray }               # 控えめ
  # カスタムも自由に追加（教科特化など）
  teigi: { color: "#0a7", bold: true }
---
```
```html
次の <span class="key">重要</span>な点、<span class="note">補足</span>です。
```

### 装飾の規則
- **プロパティは限定**: v1 は `color`・`bold`（将来 `size` 等）。任意 CSS は許さない。
- **カスタムクラスは名前と組合せが自由**、プロパティはサポート済みのみ。
- **`strong`(=`**`) / `em`(=`*`) はクラス名に使わない**（既に意味が埋まっている）。
- **未定義クラス参照はバリデートエラー**（silent な default 描画にしない）。
  styles のマージ結果が **AI に渡す「使えるクラス一覧」の契約書**になる。
- デフォルト出力色は **黒**（ライブラリ既定 `#000000`）。

## 5. テーマ / styles の3層マージと保存先

```
組込みデフォルト (Python内ハードコード)        ← ゼロ同期でも動く床
        ↓ 上書き
グローバルテーマ (D1, /api/export 相乗り)       ← 定番をここに育てる＝全員共通
        ↓ 上書き
文書 frontmatter styles                        ← その資料だけの例外
```

- **保存先は D1**（辞書と同じ場所）。`/api/export` のペイロードに `theme` を相乗りさせ、
  ツールが `data/dict.json` にキャッシュする流れにテーマも焼く。
  - 理由: ユーザー1〜2人で「全員共通」にしたい → ローカル `~/.config` は分散して不適。
    サーバ集中（D1）＋既存の同期機構で共通化が無償で手に入る。
- **ローカルキャッシュ消失は無害**（D1 が source of truth、再 sync で復元）。
  むしろローカルは D1 のオフライン・スナップショット＝保険。
- **守るべきは D1**: Time Travel（直近約30日復元）＋ エクスポートをたまに退避。

## 6. source of truth とプレビュー/編集

- **真実 = `.md`（内容＋意味装飾）＋ overrides（空間調整）の2点セット。**
- **Web UI の編集は元データに書き戻す**:
  - 色/役割の変更 → `.md` に `<span class>` を書き戻す。
  - 座標/サイズの調整 → `.md` には書かない（§3 の原則）。下記2種に保存:

| 空間編集の種類 | 例 | 保存先 |
|----------------|----|--------|
| **グリフの恒久デフォルト** | 「`・` は常に少し上」 | グローバル（D1 のテーマ/配置設定） |
| **その資料だけの一回限り** | 「この行だけ右へ」 | 文書ごとの **overrides サイドカー**（例 `lecture.overrides.json`） |

- **WYSIWYG の生命線**: プレビューを描く計算と pptx の座標生成は **同一ロジック**でなければならない。
  → 配置ロジックを **JS へ移植**し、ブラウザが dict から直接描画。Python は最終 pptx 書き出しに専念。
    配置ルール（CHAR_METRICS 等）は **辞書データ化して両者で共有**（§7）。
- 期待値: 幾何・位置・色は「見たまんま」。PowerPoint のインク質感や書き順アニメの動きまでは完全一致しない
  （プレビューは最終状態の静止表示、アニメは pptx 側でブロック単位再生）。

## 7. 配置ルールのデータ化

- 現状 `layout.py:CHAR_METRICS`・`formula.py:FORMULA_METRICS/ANCHOR_NUDGE` はハードコード。
- これを **データ化**し、組込みデフォルトを残しつつ テーマ/辞書側の値で上書き可能にする。
- 目的: (a) Python と JS レンダラが同一ルールを読む（WYSIWYG）、(b) エディタの微調整を恒久設定として書き戻せる（§6 の「恒久グリフデフォルト」）。

## 8. 認証

- **Cloudflare Access（Google ログイン＋メアド許可リスト）** に移行（現状は Basic 認証）。
  - ダッシュボード設定でほぼコード不要。無料枠50ユーザー。
  - Google Cloud / Cloudflare 側の OAuth 設定とログインはユーザー本人が行う。
- ローカル `serve` は LAN 内利用前提（必要なら簡易トークン程度）。

## 9. ユースケース（目標フロー）

```
1. PC でサイトを開く（認証ゲート通過）
2. .md をアップロード → 解析 → プレビュー生成
   （未登録文字があればプレースホルダ表示＋QR を全画面表示）
3. iPad で QR 読取 → 不足文字を登録 → サイトで「登録完了/再読込」→ プレビュー再生成
4. プレビューをマウス編集（色＝.md書き戻し / 座標＝overrides or 恒久設定）
5. output ボタン → 見たまんまの pptx 生成
```
